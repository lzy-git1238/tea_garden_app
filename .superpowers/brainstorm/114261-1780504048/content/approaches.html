3 种实现方案对比

基于现有代码架构（TeaGardenSystem + LoraManager + SQLite DataStore）

A

方案一：轻量内嵌（推荐）

新增 1 个存储类 + 1 个对话框，在 TeaGardenSystem 中内嵌定时调度逻辑。

  • ScheduleStore — SQLite 存计划 + 操作日志
  • ScheduleDialog — 计划管理（CRUD）+ 历史图表标签页
  • TeaGardenSystem 新增 1 分钟粒度的检查定时器 + 流量卡片控件

Pros

  • 改动最小，复用现有 SQLite 模式（datastore / pestdata）
  • teagardensystem.cpp 已 1604 行，增量可控
  • 对话框 + 卡片都是 Qt 标准组件

Cons

  • TeaGardenSystem 职责继续膨胀
  • 调度逻辑和 UI 耦合在一个类中
B

方案二：独立调度引擎

新增 ScheduleEngine 类，独立于 TeaGardenSystem，通过信号/槽通信。

  • ScheduleEngine — 独立的 QObject，管理所有计划 + 定时触发 + 记录日志
  • ScheduleDialog — UI 层
  • TeaGardenSystem 只做 UI 响应，调度逻辑全部在 Engine 中

Pros

  • 职责分离清晰，可独立测试
  • TeaGardenSystem 增量最小

Cons

  • 新增文件多（engine .h/.cpp + dialog .h/.cpp + store .h/.cpp = 6 个文件）
  • 信号/槽接线复杂
C

方案三：最小改动

不新增类，全部写在 TeaGardenSystem 中，用 QSettings 存计划（不用 SQLite）。

Pros

  • 改动最少，上手最快

Cons

  • TeaGardenSystem 膨胀到 2500+ 行，难以维护
  • QSettings 不适合存大量历史日志
  • 后续扩展困难
