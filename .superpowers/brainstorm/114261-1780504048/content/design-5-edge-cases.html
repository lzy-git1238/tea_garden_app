设计 · 第5节：错误处理 & 边界情况

定时计划和流量卡片的所有需要处理的异常场景

⚠️ 边界情况清单

1. 跨天灌溉

计划设置在 23:45，持续 30 分钟 → 结束时间是次日 00:15。
处理：activeJob 存完整的 QDateTime 结束时间，不是 HH:MM。

2. 计划冲突

同一设备已有计划在运行，又到了另一个计划的触发时间。
处理：正在运行时不触发新计划，新计划等待下一轮。

3. LoRa 发送失败

串口未连接或发送失败时，命令未到达设备。
处理：仍然记录日志（标记发送失败），流量卡片显示"发送失败"提示。

4. 手动干预

用户在定时计划运行期间手动点了按钮切换状态。
处理：手动覆盖定时状态 — 取消当前 activeJob，日志标记 trigger="manual"。

5. 程序重启恢复

程序关闭期间如果有定时计划该执行，重启后是否补执行？
处理：不补执行。activeJobs 存内存，重启后清空。到下一周期正常检查。

6. 流速设为0

用户把流速设置成了 0 或负数。
处理：输入校验，流速必须 > 0，否则弹提示并阻止保存。

7. 计划名称为空

新增计划时没选星期或时长为0。
处理：保存时校验 — 至少选一天、时长 > 0、时间格式正确。

🧪 测试要点

  • ✅ 创建计划 → SQLite 写入 → 重启程序 → 计划仍在
  • ✅ 编辑计划 → 下次触发按新参数执行
  • ✅ 删除计划 → 不再触发
  • ✅ 启用/停用切换 → 停用的计划不触发
  • ✅ 手动停止灌溉 → 流量卡片消失，日志正确
  • ✅ 日志查询 → 7天/30天筛选正确，图表数值正确
  • ✅ 流量卡片每秒更新 → 数值单调递增，接近真实计算值
