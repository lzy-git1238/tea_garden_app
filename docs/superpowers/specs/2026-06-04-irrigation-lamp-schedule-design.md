# 灌溉与灭虫灯定时调度功能 — 设计文档

> 日期：2026-06-04  
> 状态：设计完成，待评审

---

## 1. 功能概述

为智慧茶园管理系统的**灌溉泵**和**驱虫灯**新增以下能力：

| 功能 | 灌溉泵 | 驱虫灯 |
|------|--------|--------|
| 定时计划（多时段+按星期） | ✅ | ✅ |
| 预计流量显示 | ✅ | — |
| 实时灌溉量显示（进行中） | ✅ | — |
| 操作历史统计图表 | ✅ 灌溉量 | ✅ 运行时长 |

---

## 2. 设计决策记录

| 决策项 | 选择 | 说明 |
|--------|------|------|
| 定时触发方式 | **定时计划模式** | 设置每日/每周固定时间表，自动化无人值守 |
| 计划粒度 | **多时段 + 按星期** | 每天可有多个时段，可为不同星期配不同计划 |
| 流量数据来源 | **纯软件估算** | 不改造硬件，基于 preset_flow_rate × elapsed_time |
| 流速配置 | **全局统一** | 一个流速值适用于所有灌溉计划 |
| 管理入口 | **按钮内嵌 ⏰ 图标** | 泵/灯按钮右侧加定时图标，点击弹出对话框 |
| 流量显示 | **独立状态卡片** | 灌溉进行中时在左侧栏显示醒目的流量卡片 |
| 历史图表位置 | **对话框内标签页** | 定时管理对话框的第二个标签页 |
| 架构方案 | **轻量内嵌** | 新增 2 个类 + 1 个对话框，复用现有模式 |

## 4. 数据模型

### 4.1 schedule_config — 定时计划

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `id` | INTEGER PK | 自增主键 | 1 |
| `device_type` | TEXT | "pump" 或 "lamp" | pump |
| `days_of_week` | TEXT | 逗号分隔，1=周一，如 "1,3,5" | 1,3,5 |
| `start_time` | TEXT | HH:MM 格式 | 07:00 |
| `duration_min` | INTEGER | 持续时长（分钟） | 30 |
| `enabled` | INTEGER | 1=启用 / 0=停用 | 1 |
| `created_at` | TEXT | ISO 格式时间戳 | 2026-06-04T10:00:00 |

### 4.2 schedule_log — 执行日志

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `id` | INTEGER PK | 自增主键 | 1 |
| `device_type` | TEXT | "pump" / "lamp" | pump |
| `schedule_id` | INTEGER | FK → schedule_config.id（手动为 NULL） | 1 |
| `action` | TEXT | "on" / "off" | on |
| `trigger` | TEXT | "schedule" / "manual" | schedule |
| `flow_rate` | REAL | 当时流速 L/min（lamp 为 0） | 2.5 |
| `volume_l` | REAL | 本次累计灌溉量 L（lamp 为 0） | 37.5 |
| `ts` | TEXT | ISO 格式操作时间 | 2026-06-04T07:00:00 |

### 4.3 全局配置 — QSettings

| 键名 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `pump/flow_rate` | double | 2.5 | 灌溉泵流速 (L/min) |
| `schedule/check_interval` | int | 60 | 调度检查间隔 (秒) |
| `schedule/db_path` | string | ./schedule.db | SQLite 文件路径 |

## 5. 架构与信号流

```
┌─────────────────────────────────────────────────┐
│ TeaGardenSystem                                  │
│                                                  │
│  scheduleTimer (60s) ──→ checkSchedules()        │
│       │                          │               │
│       ▼                          ▼               │
│  ScheduleStore::queryEnabled()  sendLoraCommand()│
│       │                          │               │
│       ▼                          ▼               │
│  activeJobs (QMap, 内存)    LoraManager          │
│       │                                          │
│       ▼                                          │
│  flowCardTimer (1s) ──→ refreshFlowCard()        │
│       │                                          │
│       ▼                                          │
│  schedule_log INSERT (on / off)                  │
└─────────────────────────────────────────────────┘
```

调度流程（每分钟一次）：

1. **检查到期的关闭任务**：遍历 `activeJobs`，若 `now >= end_time`，发送关闭命令 + 记日志 + 隐藏流量卡片
2. **检查到期的开启任务**：从 SQLite 查启用的计划匹配当前星期和时间，若无冲突则发送开启命令 + 记日志 + 显示流量卡片
3. **冲突处理**：设备已在运行时跳过新触发，等下一轮

流量卡片刷新（每秒一次）：

- `current_volume = preset_flow_rate × elapsed_sec / 60`
- `expected_volume = preset_flow_rate × plan.duration_min`
- 更新 UI：已灌溉量、预计总量、剩余时间、进度条

### 6.3 定时计划管理对话框

**标签页 1 — 定时计划**：

- 上方：设备筛选下拉框 + [+ 新增计划] 按钮
- 中间：计划列表表格（序号、星期徽章、时间、时长、预计流量、启用/停用状态、编辑/删除按钮）

- 设备类型（下拉：灌溉泵/驱虫灯）

## 7. 错误处理 & 边界情况

| 场景 | 处理策略 |
|------|---------|
| 跨天灌溉 | activeJob 存完整 QDateTime 结束时间，不是 HH:MM |
| 计划冲突 | 设备运行中跳过新触发，等下一轮 |
| LoRa 发送失败 | 仍记日志（标记），流量卡片显示"发送失败"提示 |
| 手动干预 | 手动操作覆盖定时状态，取消当前 activeJob，日志标记 trigger="manual" |
| 程序重启恢复 | 不补执行，activeJobs 存内存，重启清空，下周期正常 |
| 流速设为 0/负数 | 保存时校验，流速必须 > 0，否则提示阻止 |
| 保存校验 | 至少选一天、时长 > 0、时间格式正确，否则提示 |
| 没有计划时 | 标签页显示空状态提示"暂无计划，点击新增" |
